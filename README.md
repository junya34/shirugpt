# ShiruGPT

BigQuery のデータを日本語で質問すると、Gemini が自律的に SQL を組み立てて実行し、
結果を要約して日本語で回答する Streamlit アプリです。

```
「来店データで学年別の来店件数を多い順に教えて」
        ↓
学部1年: 320,447件 / 学部2年: 154,374件 / 学部3年: 149,152件 …
（実行された SQL とグラフ・表も画面に表示）
```

> **ロジック検証用のプロトタイプです。** Streamlit Community Cloud に限定公開しており、
> 許可した利用者だけが `st.login()`（Google OIDC）でログインして使えます。
> 利用者ごとの使用量ログ・月次の使用制限にも対応済みです。Cloud Run 等への移行、
> アプリ独自の権限管理（利用者ごとに見えるデータセットを変える等）、
> Next.js への移行は次フェーズのスコープです。

# 仕組み（概要）

4 つのレイヤーが一方向に連なっています。Gemini は BigQuery に直接触れません。
**Gemini がするのは「この関数をこの引数で呼びたい」という意思表示だけ**で、
実際に接続してクエリを走らせるのは `bq_tools.py` の Python コードです。

```
┌─────────────────────────────────────────────────────┐
│ app.py            Streamlit UI                       │
│                   チャット入力・確認ダイアログ・結果表示    │
└───────────────┬─────────────────────────────────────┘
                │ agent.run(contents, ctx)
┌───────────────▼─────────────────────────────────────┐
│ src/agent.py      Gemini Function Calling ループ      │
│                   ツール呼び出しの往復・中断と再開         │
└───────────────┬─────────────────────────────────────┘
                │ 4 つのツール関数
┌───────────────▼─────────────────────────────────────┐
│ src/bq_tools.py   BigQuery アクセス                   │
│  ├ src/sql_guard.py   実行前の SQL 検査（必ず通る）      │
│  └ src/summarize.py   結果を要約に圧縮                  │
└───────────────┬─────────────────────────────────────┘
                │
┌───────────────▼─────────────────────────────────────┐
│ BigQuery                                             │
└─────────────────────────────────────────────────────┘
```

設計の中心は「**Gemini に渡すものを絞る**」ことです。データセット/テーブル一覧は
渡しますが、スキーマは明示的に要求された1テーブル分のみ、クエリ結果は要約のみ
（生データは UI 専用）です。この分離があるおかげで、SQL の検査・結果の圧縮・
キャッシュ・課金上限といった制御をすべてこちら側で強制できます。

処理ループの詳細トレース、SQL ガードの判定ロジック、コスト確認の中断・再開、
日本語データ（バッククォート必須の識別子）の扱いなどは
**[docs/architecture.md](docs/architecture.md)** にまとめています。

# クイックスタート

```bash
git clone https://github.com/junya34/shirugpt.git
cd shirugpt
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env    # GCP_PROJECT_ID などを設定
gcloud auth application-default login   # 開発者本人の認証（ADC）
.venv/bin/streamlit run app.py --server.address 127.0.0.1
```

- GCP 側の API 有効化・必要なロール、`.env` の全項目、Google ログイン（`st.login()`）
  の設定、利用ログ・月次使用制限の有効化、サービスアカウントキーを使う方式との比較は
  **[docs/setup.md](docs/setup.md)** を参照してください。
- ループバック（`127.0.0.1`）指定は必須です。付けずに起動すると同一 LAN 上の
  他端末からデータが見える状態になります。

# 既知の制約

- Streamlit Cloud に限定公開する運用を前提にしています。アプリ独自の権限管理
  （利用者ごとに見えるデータセットを変える等）や、複数アプリ・複数チームへの
  展開はまだ想定していません。
- 月次の使用制限は、同一アカウントを複数タブ・複数デバイスで**同時に**使った
  場合、判定にわずかな誤差が出ることがあります（各セッションが自分の消費量
  だけをリアルタイムに把握するため）。数十人規模の社内利用を前提に許容している
  制約で、厳密な排他制御は行っていません。
- `MAX_RESULT_ROWS` を超える結果は先頭のみ読み込まれます（画面にその旨を表示）。
- 集計クエリでも `LIMIT` が無ければ自動付与されるため、グループ数が上限を超える
  場合は切り捨てが起こります（その旨は画面と Gemini の双方に通知されます）。
- 自動テストスイートは未整備です。`src/sql_guard.py` は GCP 認証なしで単体検証
  できるため、SQL 解析まわりを変更した際は `check_sql()` を直接呼んで確認してください。
- Gemini が生成する SQL の正しさは保証されません。実行された SQL は必ず画面の
  expander に表示されるので、重要な判断に使う前に内容をご確認ください。
